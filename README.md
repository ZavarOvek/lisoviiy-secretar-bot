# Лісовий секретар

## Контекст

Це тестове завдання Broscorp на позицію Junior Python Developer, і оцінюють у ньому якість бота та повноту зібраних вимог. Замовниця тут персонаж у Telegram, Мишка-шкряботушка: це бот, з яким розробник провів інтерв'ю, щоб зібрати вимоги. Світ завдання узято з української казки "Рукавичка": ліс із вісьмома рукавичками-домівками, у кожній з яких живуть по три звірі. Ліс поділено на хвойну й листяну частини та місця біля річки, і це описує документ "Карта лісу". Звірі мають "Лісовий архів", 78 порад у файлах TXT, DOCX і PDF (19 з них скани), а бот відповідає за цими документами та приймає нові поради. У розділі про вимоги позначка [М] означає, що вимогу сформулювала сама Мишка, а [Р] рішення розробника, яке вона погодила.

## Що це

Telegram-бот "Лісовий секретар" для звірів із восьми рукавичок. Він відповідає лише за документами "Лісового архіву" й порадами, які надсилають самі звірі, і щоразу називає джерело. Відповіді пише `openai/gpt-oss-120b` на безкоштовному рівні Groq. Пошук, вибір місця й список джерел бот робить сам, без LLM.

## Спробуйте

Приклади з gold-набору ([docs/gold-questions.md](docs/gold-questions.md)):

- T18, "Які гриби біля сосон?" За Картою лісу "У соснах" це хвойний ліс, тож бот відповідає з "Грибного путівника хвойного лісу".
- T04, "Чим утеплити рукавичку під вербою?" "Під вербою" належить і листяному лісу, і річці. Бот показує обидві поради, каже, що вони різняться, і сам не вибирає.
- T02, "Коли треба утеплювати рукавичку?" Місце не назване, тому бот дає короткі варіанти для кожної частини лісу та кнопки рукавичок.
- T19 → T20, "Коли збори мешканців?" і потім "У соснах". У кожної рукавички збори свої, тож бот перепитує, про яку йдеться, а друга репліка уточнює перше питання.
- T05, "Коли Ведмідь лягає в сплячку?" Порада рукавички Ведмедя (У ліщині) важливіша за загальний Календар.
- T22, "Коли прилітають лелеки?" В архіві цього немає, і бот так і каже.
- Порада файлом. Надішліть PDF, DOCX або TXT: бот спитає ваше ім'я (лише вперше), визначить місце або попросить вибрати його кнопками і, якщо схожа порада вже є, спитає, чи це її нова версія.

## Запуск

Потрібні Docker і Docker Compose v2.

1. Токен бота: у Telegram напишіть @BotFather, команда `/newbot`, і скопіюйте токен.
2. Ключ Groq: console.groq.com → API Keys → Create API Key. Це безкоштовно.
3. Скопіюйте налаштування й впишіть у `.env` обидва значення, `TELEGRAM_BOT_TOKEN` і `GROQ_API_KEY`:

   ```bash
   cp .env.example .env
   ```

4. Запустіть:

   ```bash
   docker compose up --build
   ```

Під час першого старту Docker збирає образ (Python і tesseract з українською мовою для OCR сканів), бот застосовує міграції й імпортує 78 документів архіву з `data/archive/`. Повторний старт пропускає вже імпортовані файли. На свіжому клоні перед здачею (ноутбук розробника) збірка з нуля, `docker compose build --no-cache`, зайняла 1 хв 56 с; базові образи `python:3.12-slim` і `postgres:17` уже були в кеші Docker, тож їхнє завантаження сюди не входить. Від запуску контейнера бота до готовності минуло 23 с.

Бот готовий, коли в лозі є рядок `Run polling for bot @…`:

```bash
docker compose logs bot
```

Один токен можна запускати лише в одного бота. Якщо той самий токен уже працює деінде, Telegram віддає кожне оновлення лише одному з них, і бот відповідатиме через раз.

### Змінні `.env`

| Змінна | За замовчуванням | Що робить |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | немає | Токен від @BotFather. Обов'язкова. |
| `GROQ_API_KEY` | немає | Ключ Groq. Обов'язкова. |
| `GROQ_MODEL` | `openai/gpt-oss-120b` | Модель відповідей. |
| `GROQ_REASONING_EFFORT` | `low` | Токени міркувань теж ідуть у ліміт за хвилину; `medium` не покращив виконання інструкцій (див. "Відомі обмеження"). |
| `GROQ_FALLBACK_MODEL` | порожньо | Друга модель на випадок 429. Порожньо означає чекати й повторювати основною: `openai/gpt-oss-20b` частіше губить застереження. |
| `GROQ_MAX_COMPLETION_TOKENS` | `512` | Стеля відповіді разом із міркуваннями. Groq бронює її в ліміті ще до відповіді, тож зайве з'їдає ліміт. |
| `DIALOGUE_TTL_SECONDS` | `900` | Скільки бот пам'ятає попереднє питання, щоб прийняти "У соснах" як уточнення. |
| `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` | `lisovyi` | База в контейнері `db`. Назовні вона не відкрита. |

## Ліміти безкоштовного Groq

Для `openai/gpt-oss-120b` на момент розробки діють ліміти 8K токенів за хвилину і 200K за добу. У повному прогоні gold-набору перед здачею (31 питання, 28 викликів моделі) один виклик у середньому коштував 3 705 токенів: 3 504 prompt і 201 completion.

Groq бронює в ліміті за хвилину `prompt + max_completion_tokens` ще до відповіді, тобто ≈ 3 504 + 512 = 4 016 токенів на питання. Тому стелю відповіді тримають на 512 токенах, а не вище. Виходить ~2 питання за хвилину (8 000 / 4 016) і ~50–54 за добу на один ключ: 200 000 / 4 016, якщо добовий ліміт рахує бронь, або 200 000 / 3 705, якщо рахує фактичні токени.

Бот звертається до Groq по одному запиту за раз. Коли ліміт вичерпано, звір один раз бачить "Зараз у мене багато питань, відповім за хвилинку 🌿", а питання чекає: до 30 секунд у черзі за попереднім і ще стільки, скільки назвав Groq у відповіді 429, якщо це не більше 30 секунд. Якщо чекати довше або Groq двічі поспіль відповів 429, бот просить спитати за хвилину. У gold-прогоні так сталося з одним питанням із 31 (T23).

## Вимоги замовниці

Вимоги погоджені з Мишкою (замовницею, див. "Контекст") 29.10.2026. Позначка [М] означає, що вимогу сказала сама Мишка, [Р] що це рішення розробника, яке вона погодила або не заперечила. Тести лежать у `tests/`.

1. [М] Бот працює в особистих повідомленнях, ним користуються звірі з усіх восьми рукавичок.
   **Як зроблено:** усі роутери, крім групового, зібрано під одним фільтром "лише особисті чати" (`bot/private.py`). У групі бот відповідає тільки на `/start` і `/help` ("Я працюю лише в особистих повідомленнях…"), решту ігнорує; канали теж. У меню команд групи лише ці дві. Тести: `test_groups.py`.

2. [М] Документи з теки "Лісовий архів" є в боті з першого запуску. Як підхоплювати зміни в архіві: на розсуд розробника. [Р] Копія архіву лежить у репозиторії, при старті імпортується ідемпотентно.
   **Як зроблено:** `data/archive/` імпортується на кожному старті (`ingest/importer.py`). Незмінений файл пропускається за sha256. Змінений файл замінює активний документ того самого місця й теми, а це може бути й порада звіра, яка раніше замінила його попередню версію. Пораду звіра з власною темою імпорт не чіпає. Тести: `test_importer.py`.

3. [М] Нові поради звірі надсилають тільки файлами PDF, Word або TXT. Фото не надсилають. Звичайне текстове повідомлення це завжди питання.
   **Як зроблено:** файл приймає `bot/uploads.py`, читає `uploads/reading.py`. На фото й інші формати бот пояснює, що приймає PDF, Word (.docx) і TXT. Будь-який текст без `/` вважається питанням, крім єдиного випадку: бот щойно попросив назватися. Тести: `test_uploads.py`, `test_reading.py`.

4. [М] Бот відповідає тільки за документами й щоразу вказує документ-джерело. Для документа від звіра вказує ще, хто і коли надіслав.
   **Як зроблено:** модель отримує лише знайдені документи і повертає номери тих, на які спиралася. Блок "Джерела:" будує сам бот з назв документів, а для порад звірів додає автора й дату. Номер поза контекстом відкидається. Тести: `test_answer_service.py`.

5. [М] Хто питає, боту знати не треба. Місце звір називає в питанні сам ("які гриби біля сосон?"). Бот застосовує Карту лісу.
   **Як зроблено:** `search/places.py` знаходить у питанні рукавичку чи частину лісу за лемами й синонімами. Рукавичку бот переводить у частини лісу за чинною Картою. У пошук потрапляють лише документи названого місця, його частин і всього лісу. Тести: `test_morph_places.py`, `test_retrieval_cases.py`.

6. [Р] Місце не назване:
   - якщо відповідь різна для частин лісу, бот коротко показує варіанти для кожної частини з джерелами і пропонує назвати місце;
   - якщо відповідь своя для кожної рукавички, бот спершу перепитує, про яку рукавичку йдеться.

   Наступну репліку звіра з назвою місця бот сприймає як уточнення попереднього питання, тому потрібна коротка пам'ять розмови.
   **Як зроблено:** коли серед перших результатів є документи однієї теми з трьох рукавичок, бот перепитує рукавичку кнопками без виклику моделі. В іншому разі модель дає варіанти за частинами, а бот додає кнопки рукавичок. Якщо протягом 15 хвилин (`DIALOGUE_TTL_SECONDS`) звір надіслав лише назву місця, бот бере попереднє питання, прибирає з нього старе місце й додає нове (`answer/dialogue.py`). Тести: `test_dialogue.py`, `test_answer_service.py`, `test_bot.py`.

7. [М] Порада для конкретного місця головніша, загальну можна згадати додатково. [Р, не заперечила] Порядок: рукавичка → частина лісу → загальна порада.
   **Як зроблено:** контекст складається шарами "рукавичка → частина → весь ліс" (`search/retrieve.py`), кожен документ підписаний своїм шаром, а системний промпт велить тримати цей порядок. Тести: `test_retrieve.py`, `test_retrieval_cases.py`.

8. [Р] "Під вербою", коли поради листяного лісу й річки розходяться: бот показує обидві з джерелами, прямо каже, що вони різняться, і сам не вибирає.
   **Як зроблено:** чи є конфлікт, вирішує детектор (`search/conflicts.py`), а не модель. Далі модель заповнює окремий пункт для кожної частини, а вступ "…поради для них різняться" і фразу "Оберіть ту, що підходить саме вашому місцю" пише бот. Тести: `test_conflicts.py`, `test_answer_service.py`.

9. [Р] Відповіді в документах немає: бот чесно каже про це, нічого не вигадує, пропонує уточнити питання або надіслати документ. Відповідь знайшлася частково: бот відповідає на цю частину з джерелом і каже, чого бракує.
   **Як зроблено:** якщо пошук нічого не знайшов, бот відповідає "не знайшов" без моделі. Якщо документи є, але відповіді в них немає або вона часткова, модель повертає вид відповіді `not_found` або `partial`. Непридатну відповідь бот запитує ще раз, а після другої каже, що не може відповісти впевнено. Тести: `test_answer_service.py`.

10. [М] Новіший варіант того самого документа для того самого місця замінює старий, і звірі бачать тільки новий. Окрема порада не скасовує стару лише через дату, вона ранжується за конкретністю. [Р] Спосіб розпізнавання це рішення розробника, Мишка це прямо підкреслила: бот класифікує документ за типом і місцем; якщо такий уже є, питає звіра кнопкою "замінити?". Старий варіант лишається у внутрішній історії, але з пошуку зникає.
    **Як зроблено:** бот визначає місце нової поради, шукає серед порад того самого місця кандидата з тією самою темою або схожим змістом (`uploads/versions.py`) і питає "Замінити стару" чи "Залишити обидві". Замінена порада отримує статус `replaced` і зникає з пошуку. Якщо бот кандидата не побачив, звір може сам указати стару пораду кнопкою "Це нова версія іншої поради?". Тести: `test_versions.py`, `test_upload_service.py`, `test_uploads.py`.

11. [М] Замінювати документи може будь-який звір, адмінів немає ("у лісі всі рівні").
    **Як зроблено:** заміна не перевіряє автора, тож звір може замінити і архівний документ, і чужий. Тести: `test_upload_service.py` (архівний), `test_delete.py` (чужий, у ланцюжку замін).

12. [М] Коли звір уперше надсилає документ, бот просить назватися справжнім ім'ям і запам'ятовує його. Ім'я в Telegram для цього не годиться. Для питань ім'я не потрібне. [Р] Документ чекає, поки звір назветься. Ім'я можна змінити командою.
    **Як зроблено:** ім'я зберігається в таблиці `beasts`, документ чекає в пам'яті до 30 хвилин. Змінити ім'я можна командою `/name`. Тести: `test_uploads.py`, `test_upload_service.py`.

13. [Р] Видалити звір може тільки документ, який надіслав сам. Архівні й чужі документи можна тільки замінити. Видалення м'яке.
    **Як зроблено:** `/my` показує лише власні активні поради з кнопкою видалення і підтвердженням. Видалення ставить статус `deleted`, а якщо порада замінила іншу, та повертається. Тести: `test_delete.py`, `test_library.py`.

14. [М] Мова відповідей українська, тон простий, доброзичливий, без технічних слів.
    **Як зроблено:** так велить системний промпт (`answer/prompt.py`), а `clean_text` прибирає з відповіді розмітку і згадки "(джерело N)". Усі тексти бота звертаються на "ви", і тест ловить звертання на "ти". Тести: `test_texts.py`, `test_answer_service.py`.

15. [Р] Карта лісу не прописана в коді. Завжди використовується чинний варіант документа "Карта лісу", тож після підтвердженої заміни бот одразу відповідає за новою картою.
    **Як зроблено:** легенду Карти бот розбирає з документа (`ingest/forest_map.py`) у таблицю `forest_map`. Звір може надіслати нову "Карту лісу", і після підтвердження бот перебудовує пошук. Тести: `test_forest_map.py`, `test_upload_service.py`, `test_delete.py`.

16. [Р] Перегляд документів: список, згрупований по рукавичках, частинах лісу й загальних порадах, з автором і датою. Окремо: список "мої документи" з видаленням.
    **Як зроблено:** `/docs` показує кнопки груп (рукавички, частини лісу, весь ліс) і список документів групи з автором і датою, а `/my` власні поради з видаленням. Тести: `test_library.py`.

17. [Р] Перше відкриття (/start): привітання, коротко про архів і поради від звірів, приклад питання з місцем, як надіслати пораду (PDF/Word/TXT).
    **Як зроблено:** текст `/start` лежить у `bot/handlers.py`. Тести: `test_bot.py`.

18. [Р] Сповіщення: за замовчуванням бот нікому не пише сам. Охочі підписуються на нові поради й можуть відписатися. Повідомлення підписнику містить, що змінилося (нова порада чи заміна якого документа), для якого місця і хто надіслав. Автор сповіщення про власний документ не отримує. Фільтр за місцем відкладено.
    **Як зроблено:** `/subscribe` і `/unsubscribe`. Розсилка (`notify.py`) іде у фоні, автора пропускає, а того, хто заблокував бота, відписує. Тести: `test_notify.py`, `test_library.py`.

### Технічні рішення без питань до замовниці

Формат `.doc` не підтримується: бот просить зберегти файл як `.docx`. На фото й інші формати він ввічливо пояснює, які формати приймає. Скановані PDF від звірів проходять той самий OCR, що й архівні.

## Суперечності в архіві і як бот їх розв'язує

У дужках номери питань gold-набору, які їх перевіряють ([docs/gold-questions.md](docs/gold-questions.md)).

1. **Утеплення** (T01, T02, T21). Календар каже "у листопаді", порада хвойного лісу "у жовтні", а листяного "коли облетить листя, до першого снігу". Для хвойного лісу бот відповідає "у жовтні" і може згадати Календар як загальну пораду.
2. **Сплячка** (T05, T06). Календар каже "у грудні", а Ведмідь (У ліщині) і Їжак (На узліссі) лягають з листопада. Порада рукавички головніша.
3. **Брід** (T07). Біля річки брід вище греблі безпечний, коли гребля відкрита і вода спала. Для "Біля бобрової греблі" вбрід не можна ніколи, тільки по греблі. Перемагає порада рукавички.
4. **Горіхи й жолуді** (T09, T11). Підсумок Календаря про жолуді й горіхи у жовтні суперечить його ж тексту. Бот спирається на окрему пам'ятку: горіхи з кінця серпня, жолуді з середини вересня до кінця жовтня.
5. **Під вербою** (T04, T12). Гриби ростуть на 4–5 день після дощу (листяний ліс) або наступного дня (річка). Для утеплення радять дубове листя або очерет на корінні. Бот показує обидва варіанти і не вибирає (вимога 8).
6. **Дощ біля річки** (T13). Після сильного дощу до берега два дні не підходити, а опеньки йдуть наступного дня після невеликого дощу. Відповідь має містити обидва факти.
7. **Вечір під дубом** (T14). Восени ввечері під дубами не ходити через кабанів, а гостей у "Під дубом" приймають тільки ввечері. Бот дає правило рукавички, показує застереження і каже, що поради різняться.
8. **Мисливці на просіці** (T15, T27). У маршруті "Під ялиною → до дуба через просіку" застереження немає, а "Під дубом" каже, що просікою по суботах ходять мисливці. Бот має додати застереження до маршруту; у прогоні перед здачею модель його загубила (див. "Відомі обмеження").
9. **Зайчик і вирубка** (T16). У соснах кора осик на вирубці годиться для Зайчика, але вночі на вирубці полює пугач. Бот називає обидва факти.
10. **Сигнали Сороки** (T17). Три короткі крики означають мисливців, для всього лісу. Якщо Сорока скрекоче двічі, поруч чужий звір, і це лише У ліщині. Бот має дати загальну відповідь і згадати виняток; загальна порада тут часом випадає (див. "Відомі обмеження").
11. **"Які гриби біля сосон?"** (T18). У "У соснах" немає грибної пам'ятки, тож через Карту лісу відповідь береться з "Грибного путівника хвойного лісу".

Пізніше, під час збирання gold-набору, знайшлися ще дві:

- **T10**: горіхи в соснах. Пам'ятка листяного лісу там не діє, і бот її не застосовує.
- **T28**: гриби на узліссі. Грибні путівники частин лісу там не діють, бо узлісся не належить жодній частині.

## Рішення, яких вимоги прямо не задають

Питання T05, T14, T17 і T23 розібрано в розділі "Рішення розробника" файлу [docs/gold-questions.md](docs/gold-questions.md).

Для 19 сканів архіву зроблено вивірені вручну транскрипти в `data/transcripts/`, прив'язані до sha256 файлу. OCR спрацьовує, лише якщо файл змінився, і для нових сканів: на фоні "береста" він плутає цифри ("350 кроків" перетворюється на "850").

Числа з нового скану бот перепитує кнопками, і це називається "поганий зір". Якщо числа неправильні, бот просить надіслати .docx або .txt.

Місце нової поради спершу визначають правила (назва, вступне речення, рукавичка в лапках), а якщо вони не спрацювали, бот показує кнопки. LLM тут не бере участі.

Видалення поради, яка замінила іншу, повертає замінену. Знання з архіву видалення не стирає.

Вимогу 8 виконує код: детектор вирішує, чи є конфлікт, а модель лише заповнює окремий пункт для кожної частини. Вступ і фразу "Оберіть ту, що підходить саме вашому місцю" пише бот.

Весь бот звертається до звірів на "ви": на "ти" модель уперто зісковзувала на "ви".

Джерела будує бот. Модель повертає номери документів, а назви підставляє бот, тому вигадане джерело неможливе.

## Як перевірено

Тести з базою працюють з окремою базою з `DATABASE_URL` і щоразу створюють її наново:

```bash
set -a; . ./.env; set +a
docker compose run --rm \
  -e DATABASE_URL="postgresql+asyncpg://$POSTGRES_USER:$POSTGRES_PASSWORD@db/lisovyi_test" \
  bot pytest -q -rs
```

Перед здачею 677 тестів пройшли, 0 пропущено, за 12 хв 40 с на ноутбуці розробника. Telegram у тестах замінено записом запитів, Groq фейком, а базу дає PostgreSQL з контейнера `db`.

Gold-набір складається з 31 питання. Для кожного записано очікувану поведінку, документи, що мають бути серед джерел, і те, що відповідь має й не має сказати: [docs/gold-questions.md](docs/gold-questions.md). Прогін по справжньому Groq:

```bash
docker compose stop bot
docker compose run --rm -v "$PWD:/app" bot python scripts/run_gold.py
docker compose start bot
```

Бота варто зупинити, щоб він не ділив з прогоном ліміт за хвилину. У повному прогоні перед здачею вид відповіді збігся з очікуваним у 28 з 31 питань, а всі обов'язкові джерела були серед джерел відповіді в 26 з 31. Витрачено 103 748 токенів (98 115 prompt і 5 633 completion), ≈52% добового ліміту, за 11 хвилин. Розбіжності: T13 і T11 описано у "Відомих обмеженнях", T23 у "Лімітах безкоштовного Groq".

Скрипт перевіряє лише вид відповіді й джерела. Зміст відповідей перевірено вручну за полями "Має сказати" і "Не має" gold-набору, і так знайдено обмеження нижче.

## Відомі обмеження

Їх виявили вручну в живих прогонах gold-набору. Вони пережили дві версії промпту й `reasoning_effort=medium`. Наступний крок це модель, що краще тримає інструкції, але на безкоштовному Groq такої немає.

- Злиття порад для різних випадків. T08: до переправи по камінню біля верби модель додає умову броду вище греблі ("переконайтеся, що бобри відкрили греблю").
- Власні висновки. T26: "до першого снігу — це зазвичай листопад".
- Неточні дієслова й прийменники. T10: "падають" замість "збирають"; T27: "на північ" замість "на півночі".
- Загальна порада часом випадає (T07, T17), хоча документ є в джерелах.
- Узагальнення адресата. На "Що їсти під вербою?" модель відповіла "можна їсти комарів і мошки", хоча в записі це частування для Жабки й Горобця.
- Дрібні домисли в переказі: "берег, затоплений під час дощу" замість "берег, який заливало".
- Ліміти безкоштовного Groq: ~50–54 питання на добу на один ключ і ~2 за хвилину (див. "Ліміти безкоштовного Groq").
- OCR нових сканів плутає цифри. Тому бот перепитує числа, але текст поза числами не перевіряє.

Наступні випадки знайшов єдиний повний прогін gold-набору перед здачею (`reasoning_effort=low`). З іншими версіями промпту й `reasoning_effort=medium` їх окремо не перевіряли:

- Хибне "немає в записах". T13: обидва потрібні документи ("Грибний путівник біля річки" і "Небезпеки біля річки") були в контексті, а модель відповіла, що інформації немає.
- Застереження з іншого документа губиться. T15: маршрут "Під ялиною → до дуба" через просіку без суботнього застереження про мисливців, хоча документ "Під дубом" був у контексті.
- Варіанти за частинами не завжди. T11: на "Коли збирати горіхи?" модель дала лише пораду листяного лісу, без варіантів для інших частин.
- Помилки в словах. T28: "кри́льце на ніжці" замість "кільце"; "запитайте у Їжак".

Попри це джерела завжди справжні, "не знайдено" й перепитування рукавички детерміновані, а поради з іншого місця в контекст не потрапляють: 45 з 45 кейсів пошуку (`tests/test_retrieval_cases.py`).

## Що далі

Відкладено фільтр сповіщень за місцем (вимога 18). Варто перейти на модель, що краще тримає інструкції, коли вона з'явиться на доступному рівні Groq. Назви й відмінки частин лісу зараз описано в кількох модулях, їх можна звести в одну таблицю. Для швидших тестів корисна шаблонна БД: зараз кожен тест з базою створює її наново й проганяє міграції, тож повний прогін триває ~13 хвилин.

## Архітектура

Модуль `ingest/` читає PDF, DOCX, TXT і скани, класифікує документи за місцем і імпортує архів. `search/` розпізнає місце за чинною Картою і збирає контекст BM25 за шарами "рукавичка → частина → весь ліс". `answer/` питає Groq зі strict JSON-схемою, перевіряє відповідь і будує список джерел. `uploads/` приймає поради звірів: текст, місце, нова версія чи окрема порада. `notify.py` розсилає сповіщення підписникам, а `bot/` тонкий шар aiogram. Дані лежать у PostgreSQL: документи зі статусами `active` / `replaced` / `deleted`, звірі, підписки, Карта лісу.

Докладно, зі шляхом питання й поради та числами за рішеннями: [docs/architecture.md](docs/architecture.md).

Як бот створювався етап за етапом, з поворотами й перевірками: [docs/process.md](docs/process.md).
