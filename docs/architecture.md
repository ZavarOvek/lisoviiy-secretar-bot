# Архітектура «Лісового секретаря»

Документ для того, хто відкриє код. Що бот уміє і чому так вирішено з погляду замовниці, описано в [README](../README.md).

## 1. Модулі

Код лежить у `src/lisovyi/`.

| Модуль | Що робить |
|---|---|
| `ingest/` | Читає файли (`parsers.py`: PDF, DOCX, TXT; `ocr.py`: tesseract `ukr`), класифікує документ за типом і місцем (`classify.py`), розбирає «Карту лісу» (`forest_map.py`), ідемпотентно імпортує архів на старті (`importer.py`). |
| `search/` | Леми pymorphy3 і синоніми (`morph.py`, `synonyms.py`), розпізнавання місця за чинною Картою (`places.py`), BM25 (`index.py`), збирання контексту за шарами (`retrieve.py`), детектор конфлікту частин лісу (`conflicts.py`), знімок індексу з БД (`service.py`). |
| `answer/` | Системний промпт і JSON-схеми (`prompt.py`), клієнт Groq із чергою на 429 (`llm.py`), коротка пам'ять розмови (`dialogue.py`), складання відповіді (`service.py`), тексти відповідей (`texts.py`). |
| `uploads/` | Читання файлу від звіра (`reading.py`), пошук кандидата на нову версію (`versions.py`), збереження, заміна, видалення, ім'я звіра (`service.py`). |
| `notify.py`, `library.py` | Підписки й розсилка сповіщень; списки порад для `/docs` і `/my`. |
| `bot/` | Хендлери aiogram: питання (`handlers.py`), завантаження (`uploads.py`), `/help`, `/docs`, `/my`, підписки (`library.py`), кнопки місць (`places.py`), групові чати (`groups.py`), усі тексти бота (`texts.py`). |
| `db/` | Моделі SQLAlchemy і сесії; міграції Alembic лежать у `migrations/`. |

`ingest`, `search`, `answer`, `uploads` і `library.py` від aiogram не залежать: їх тестують без Telegram, а `scripts/run_gold.py` викликає `AnswerService` напряму. aiogram імпортують лише `bot/`, `__main__.py` і `notify.py` (розсилка сама надсилає повідомлення).

`python -m lisovyi` (`__main__.py`): міграції → імпорт архіву → побудова індексу → polling.

## 2. Шлях питання

Детерміновано все, крім одного кроку: тексту відповіді, який пише модель.

1. **Текст.** Звичайне повідомлення в особистому чаті завжди є питанням (вимога 3). У групах бот мовчить (`bot/groups.py`).
2. **Уточнення.** `DialogueMemory.merge` → `merge_followup`: якщо бот щойно перепитав місце, а звір відповів лише назвою місця («У соснах»), її дописують до попереднього питання. Пам'ять живе `DIALOGUE_TTL_SECONDS` (900 с).
3. **Місце.** `PlaceResolver` шукає в питанні рукавички й частини лісу за лемами і застосовує чинну «Карту лісу» з таблиці `forest_map`: «У соснах» → хвойний ліс, «Під вербою» → листяний ліс і біля річки.
4. **Режим** (`retrieve.py`):
   - `placed` — місце назване: лише документи названих рукавичок, дозволених частин і всього лісу; поради чужих місць у контекст не потрапляють;
   - `unplaced` — місце не назване: шість найкращих документів з усіх шарів;
   - `ask_glove` — серед чотирьох найкращих є документи однієї теми з трьох різних рукавичок: бот перепитує рукавичку кнопками, без LLM;
   - `not_found` — жоден документ не набрав рахунку: «не знайшов», без LLM.
5. **Контекст.** BM25 за шарами «рукавичка → частина → весь ліс», до трьох документів на кожну рукавичку, частину й весь ліс, бюджет 6000 символів. Документи йдуть цілими, без нарізання на фрагменти.
6. **Детектор конфлікту** (`conflicts.py`, вимога 8). Якщо названа рукавичка належить двом частинам лісу, у кожної частини є свій найкращий документ, ці документи однієї теми і порада рукавички слабша за них, то відповідь будується по частинах.
7. **Groq** (`openai/gpt-oss-120b`, `reasoning_effort=low`) зі strict JSON-схемою: модель повертає текст і номери документів-джерел. Для конфлікту схема інша: окремий пункт для кожної частини й загальний.
8. **Валідація.** Номери джерел мають бути з пакета контексту, пункт частини має посилатися на документ своєї частини. Непридатна відповідь — ще одна спроба; після двох конфліктна відповідь іде звичайним шляхом.
9. **`clean_text`** прибирає розмітку (`**`, `#`), згадки «(джерело N)» і присвійне «ваша рукавичка»; для пунктів частин `drop_part_label` прибирає назву частини, яку модель повторила на початку.
10. **Джерела** будує бот: назва, місце, а для поради від звіра ще автор і дата. Назву документа модель не пише, тож вигадати джерело не може.

На 429 `LLMClient` чекає й повторює. Звір один раз бачить «відповім за хвилинку».

## 3. Шлях поради від звіра

1. **Формат** (`uploads/reading.py`): PDF, DOCX, TXT. На `.doc` бот просить зберегти як `.docx`, на фото й інші формати пояснює, які приймає.
2. **Текст.** Текстовий шар PDF, DOCX або TXT. Для скану — OCR. Якщо OCR знайшов числа, бот показує їх і питає кнопками, чи вони правильні («поганий зір»). Якщо ні, просить надіслати `.docx` або `.txt`.
3. **Ім'я.** Хто надсилає вперше, мусить назватися. Файл чекає в пам'яті процесу 30 хвилин.
4. **Місце** (`ingest/classify.py`, `classify_upload`): правила без LLM, по черзі — назва архівного вигляду, рукавичка в лапках у вступі, частина лісу чи весь ліс у вступі, маркери частини в назві. Якщо правила не спрацювали, бот показує кнопки місць.
5. **Нова версія чи окрема порада** (`uploads/versions.py`): BM25 серед активних документів того самого місця. Кандидат є, якщо тема збіглася або рахунок першого документа щонайменше в 1,8 раза більший за другий; для місця з одним документом потрібні три спільні рідкісні леми. Остаточно вирішує звір кнопками «Замінити стару» / «Залишити обидві». Якщо кандидата немає, під підтвердженням є кнопка «Це нова версія іншої поради?».
6. **Збереження** (`uploads/service.py`): нова порада стає `active`; замінена отримує статус `replaced`, а нова — `replaces_id` на неї. Пошуковий індекс перебудовується одразу після збереження, заміни чи видалення. Нова «Карта лісу» оновлює `forest_map`.
7. **Сповіщення** (`notify.py`): фонова розсилка підписникам, крім автора, з паузою 50 мс між повідомленнями.

## 4. Модель даних

| Таблиця | Що зберігає |
|---|---|
| `documents` | Текст, тип (`glove` / `part` / `general` / `map`), місце (`scope`), тема (`topic`), sha256, джерело тексту (`text` / `transcript` / `ocr`), автор (NULL для архіву), статус `active` / `replaced` / `deleted`, `replaces_id`. |
| `beasts` | Telegram id і справжнє ім'я звіра. |
| `subscriptions` | Чати, підписані на сповіщення. |
| `forest_map` | Легенда чинної Карти: рукавичка → частини лісу і порядок у легенді. |

Частковий унікальний індекс `uq_documents_active_scope_topic` на `(scope, topic) WHERE status = 'active'`: для одного місця й теми активна лише одна версія. Заміна і видалення нічого не стирають. Видалення поради, яка замінила іншу, повертає замінену в `active`.

## 5. Чому так

| Рішення | Число |
|---|---|
| Без ембедингів: Groq їх не дає, а BM25 + фільтр за Картою дають потрібне | 45 з 45 кейсів пошуку, 0 документів не з того місця (`tests/test_retrieval_cases.py`) |
| Лема — множина з усіх розборів pymorphy3 | перший розбір хибить: «соснах» → «сосни» |
| Цілі документи замість фрагментів | вибір фрагментів губив ключові факти |
| Правила місця для завантажень | 56 з 56 порад рукавичок архіву під назвою «порада» знаходять свою рукавичку (`tests/test_classify_upload.py`) |
| Поріг версії 1,8 | 77 з 77 документів архіву впізнано з 40% їхніх речень; на десяти випадкових зернах — не менше 99% (`tests/test_versions.py`) |
| Вимога 8 детектором, а не промптом | три версії промпту й `reasoning_effort=medium` не змусили модель не вибирати |
| Статичний системний промпт першим | кеш Groq; захищено тестом на sha256 |
| Без запасної моделі `gpt-oss-20b` | частіше губить застереження |
| Транскрипти 19 сканів | OCR плутає цифри: «350» → «850» |
